BONOBO FILE MANAGER 1.2.7 — CORRECTION FTP ET AJOUT FTPS

Version conservée : 1.2.7 ; versionCode conservé : 8.
La variante d’essai reste 1.2.7-preview, comme l’APK précédent.

DIAGNOSTIC DU JOURNAL FILEZILLA

Le message « 421 Maximum login limit has been reached » était causé par
l’absence de ConcurrentLoginPermission dans les autorisations du compte
bonobo. Apache FtpServer vérifie cette autorisation dès USER ; sans elle,
il refuse même une première connexion. Ce refus ne prouvait donc pas que
d’autres utilisateurs étaient déjà connectés.

Les réponses 431 à AUTH TLS et AUTH SSL venaient de l’absence de configuration
TLS dans le serveur précédent. Il s’agissait de deux problèmes distincts.

CORRECTIONS APPORTÉES

1. Connexion
- Ajout de ConcurrentLoginPermission : 10 sessions au total, 5 par adresse IP.
- Ajout explicite des autorisations de transfert et de l’écriture.
- Compte bonobo, mot de passe choisi et confirmé, minimum 8 caractères.
- Mot de passe toujours conservé seulement en mémoire pendant le service.

2. Chiffrement
- FTPS explicite sur le port 2121, avec AUTH TLS.
- TLS 1.2 activé pour compatibilité avec Android 8 et versions suivantes.
- USER et PASS refusés sur une connexion non chiffrée.
- Canal de données chiffré par défaut, y compris sans demande PROT du client.
- PROT C et CCC refusés : aucun retour au transfert ou contrôle en clair.
- Mode passif ; contrôle de l’adresse IP de la connexion de données.
- Le répertoire partagé reste Téléchargements/Bonobo-Partage.

3. Certificat
- Certificat local propre à chaque installation, conservé entre les démarrages.
- Clé EC P-256 créée dans AndroidKeyStore, non exportée vers un fichier.
- Empreinte SHA-256 affichée dans l’application et sélectionnable pour copie.
- Le certificat n’est pas signé par une autorité publique : FileZilla demandera
  de lui faire confiance. La comparaison de l’empreinte est nécessaire pour
  authentifier le téléphone, et pas seulement chiffrer la connexion.
- Un avertissement concernant le nom du certificat et l’adresse IP est attendu.
  Ne l’accepter que si l’empreinte correspond exactement à celle du téléphone.
- Une réinstallation avec effacement des données produit une nouvelle identité.

4. Service et écran FTP
- Démarrage du serveur et génération de la clé hors du thread de l’interface.
- État « Démarrage sécurisé… » et message explicite si le démarrage échoue.
- Arrêt nettoyant les sessions et les informations temporaires affichées.
- Instructions FileZilla et empreinte ajoutées à l’écran FTP, rendu défilant.
- La page À propos et les arrangements validés précédemment sont conservés.

CONFIGURATION FILEZILLA POUR TON ESSAI

Ouvrir le Gestionnaire de sites et créer ou modifier le site :

  Protocole : FTP — Protocole de Transfert de Fichiers
  Hôte : 192.168.1.145 (ou l’adresse actuellement affichée par Bonobo)
  Port : 2121
  Chiffrement : Exiger une connexion FTP explicite sur TLS
  Type d’authentification : Demander le mot de passe
  Identifiant : bonobo
  Mot de passe : celui saisi dans Bonobo au démarrage du serveur
  Paramètres de transfert : mode Passif

Arrêter l’ancien serveur, installer cette correction et redémarrer le serveur
avec un mot de passe confirmé. Le téléphone et le PC doivent être joignables
sur le réseau local. À la première connexion, comparer dans FileZilla
l’empreinte SHA-256 du certificat avec celle affichée par Bonobo.

Pour l’essai : afficher le dossier, envoyer un petit fichier, le télécharger,
puis fermer et rouvrir la connexion. Si un nouveau problème survient, transmettre
le journal FileZilla et le message éventuel dans Bonobo, sans le mot de passe.

LIMITES DE CETTE VALIDATION

Les tests FTPS sont effectués sur JVM avec un certificat de test généré à
l’exécution. Ils ne remplacent pas un essai FileZilla sur ton téléphone :
AndroidKeyStore, son fournisseur TLS et ton réseau local restent à valider
sur appareil. Aucun test sur téléphone ni émulateur n’a été réalisé ici.
La variante release n’a pas été compilée ni signée dans cet environnement.
Cette modification sécurise le serveur FTP ; le transfert direct HTTP constitue
un autre service et n’est pas converti en HTTPS par ce correctif.
