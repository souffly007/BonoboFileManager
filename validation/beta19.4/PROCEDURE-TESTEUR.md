# Procédure testeur — bêta 19.4

À effectuer par le testeur sur un appareil de test avec une version installable préparée par son circuit habituel. L'APK livrée est non signée et ne s'installe pas directement. Aucun essai matériel n'a été exécuté pendant la préparation de cette livraison. Utiliser uniquement des supports et fichiers factices, conserver une source de référence et éviter le NAS.

1. Démarrer l'application, ouvrir Paramètres → Diagnostic technique : interrupteur désactivé. Exporter après effacement : journal vide. Effectuer une copie factice diagnostic désactivé ; exporter à nouveau : toujours vide.
2. Activer. Connecter la clé, sélectionner manuellement son dossier avec droits lecture/écriture. Copier un petit fichier, puis un grand fichier (> 2 Gio si possible) ; attendre la fin. Exporter vers un document local et vérifier USB_*, SAF_PERMISSION, COPY_START/COPY_END, octets/durée, STREAMS_CLOSED, SHA256 MATCH et PUBLICATION. Une copie SAF peut produire plusieurs écritures/vérifications pour la publication. Vérifier le contenu de destination indépendamment, après éjection sûre et reconnexion.
3. Comparer sur le même support plusieurs copies diagnostic actif puis inactif, sans changer les fichiers ni les conditions. Relever les durées ; aucune dégradation importante ne doit être attribuable au journal. Les tests JVM ne mesurent pas les performances d'un vrai fournisseur USB.
4. Tester un déplacement vers SAF : la source doit rester conservée et le déplacement incomplet conformément à la bêta 19.3. Vérifier MOVE puis SOURCE_RETAINED. Le renommage SAF de production reste refusé. Ne pas contourner ce refus.
5. Supprimer un document factice avec la confirmation habituelle : DELETE puis DISAPPEARANCE OK uniquement après contrôle du parent. Révoquer les droits ou retirer le support pendant une opération factice : résultat REFUSED/ERROR/INDETERMINATE, sans succès trompeur. Les résidus et reçus restent traités comme en 19.3.
6. Annuler une grosse copie : CANCEL, COPY_END CANCELLED si le flux était en cours, puis CLEANUP. Examiner les éventuels résidus dans l'interface. Vérifier qu'aucune source ni fichier préexistant n'a été supprimé.
7. Reproduction après un autre explorateur : effacer le journal, activer, réussir une copie témoin, quitter vers l'autre explorateur, utiliser uniquement le support factice, revenir dans Bonobo et refaire la même opération. Exporter après l'échec éventuel. APP_RESUMED et SAF_FAILURE donnent une chronologie ; aucune cause liée à l'autre application n'est affirmée automatiquement. Noter séparément la séquence d'actions, sans joindre de noms/URI personnels.
8. Exporter puis rechercher les noms factices choisis, chemins, `content://`, adresses, messages et empreintes : aucun ne doit figurer dans les traces. Seuls des UUID temporaires d'opération sont attendus. L'export précédent reste présent après l'effacement du journal local.
9. Effacer : annuler d'abord la confirmation et vérifier les traces conservées ; confirmer ensuite et réexporter au repos : vide. Avec diagnostic actif, de nouveaux événements peuvent apparaître après effacement. Désactiver, effectuer des opérations et vérifier qu'aucune nouvelle trace n'apparaît. Redémarrer complètement le processus : l'interrupteur revient à désactivé.
10. Pour la rotation, répéter assez d'opérations factices pour dépasser 1 Mo de traces : export ≤ 1 000 000 octets et événements anciens remplacés. Les tests JVM exercent cette rotation avec un plafond réduit. La saturation de file peut abandonner des événements, sans bloquer les opérations.

Renseigner modèle/version Android, type de fournisseur/support sans numéro de série, étapes, résultat attendu/observé et export volontaire. Les erreurs disque, la confidentialité structurelle et le blocage simulé d'un export sont couverts par les tests JVM ; ne pas remplir volontairement le stockage du téléphone principal.
